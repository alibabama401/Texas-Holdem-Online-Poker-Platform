公开边界与评估建议

当前仓库不是可直接构建的完整平台。 可见 C++ 文件引用了仓库中未包含的头文件与服务实现；Unity 仅有场景 `.meta`；未见完整构建配置、数据库脚本、服务入口或客户端工程。README 和 Pages 因此只描述能够由公开文件与截图证明的内容。

常见问题

可以直接编译运行吗？

不能仅凭当前公开文件完成构建。应先补齐 Tars/项目私有依赖、缺失头文件、服务实现、配置、数据库和 Unity 场景资源。

支持哪些玩法？

协议和截图可验证经典德州、SNG 与 MTT 场景，俱乐部消息结构也已公开。其他玩法需按实际分支和交付内容验证。

API 文档是否等于实现？

不等于。`api_documentation.md` 是接口参考，不能代替服务端实现、集成测试和网络抓包验证。

许可证如何确认？

根 `LICENSE` 为 MIT，但 `License.md` 与 `CITATION.cff` 存在不同授权描述。使用前应由仓库维护者统一授权文件。
